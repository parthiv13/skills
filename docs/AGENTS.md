## Always-on skills

Read all three before every response, in every workflow.

- [Grown-ups](../skills/grown-ups/SKILL.md): answer questions first, no leading questions, ask only when confused.
- [Doubt-driven development](../skills/doubt-driven-development/SKILL.md): every claim is verifiable. Assumptions in bold, work shown, real thing checked.
- [Unslop](../skills/unslop/SKILL.md): strip AI tells from all writing.

## Evidence and uncertainty

- Do not infer nonexistence from a failed name or pattern search.
- Distinguish “not found” from “does not exist.”
- When repository-specific behavior is uncertain, ask a focused clarification question before making a definitive recommendation. This covers facts only the user holds. It does not cover choices between paths, which follow the grown-ups skill, section 3.
- State uncertainty explicitly when authoritative verification is unavailable.

## Validation

- Choose validation that fits the change. Prefer focused, established repository checks when available; do not invent ad-hoc commands or scripts when direct inspection is sufficient. Run commands when they meaningfully verify behavior, use an established check, or are requested by the user.
